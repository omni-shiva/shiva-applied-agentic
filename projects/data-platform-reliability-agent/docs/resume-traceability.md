# Resume traceability and confidentiality boundary

This repository is an independent synthetic implementation. It is designed to make public resume
themes easier to demonstrate and discuss; it is not a reconstruction of an employer platform.

| Public resume theme | Portfolio translation | Deliberately excluded |
|---|---|---|
| Data-product contract automation across many pipelines | Synthetic expected/observed schemas, diffs and regression tests | Employer schemas, DDLs, templates, prompts and repositories |
| AI-assisted generation and validation workflow | Versioned evaluation cases, repeatable metrics and approval gates | Internal evaluator names, production datasets and scoring rules |
| Production incident diagnosis and retrieval | Qdrant runbooks, SQL event evidence and bounded tools | Employer retrieval architecture, operational data and incident history |
| Lakehouse observability and SLA monitoring | Run IDs, error codes, latency, volume, SLA and evidence output | Internal dashboards, alert rules, infrastructure and cost details |
| Logging migration and standardization | Synthetic correlation-field runbook and logging-gap case | Logging vendor configuration, migration code and security controls |
| Spark optimization | Generic shuffle, skew, partition and canary guidance | Workload code, cluster settings, dataset structure and tuning values |

## Safe interview wording

> This public project is an independent, synthetic implementation inspired by the problem classes
> in my resume. My production experience and this repository are related at the level of engineering
> patterns—contracts, reliability, retrieval, evaluation and approval—but the repository contains no
> employer code or internal architecture.

When discussing the repository, describe exactly what the code implements. Do not claim that the
synthetic dataset, feature-hash embeddings, FastAPI wrapper or public tool schemas were deployed at
an employer unless separate evidence supports that statement.
